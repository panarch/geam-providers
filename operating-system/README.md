# geam-operating-system

This crate implements `name/0`, the only Erlang external of the unmodified [`operating_system` 1.0.1](https://hex.pm/packages/operating_system/1.0.1) Gleam package, through Geam's public typed provider API. Add `operating_system` to the Gleam project and select `geam-operating-system` as its Geam provider. The verified package range is limited to `>= 1.0.1 and < 1.0.2`.

The original package returns a lowercase operating-system name. Its Erlang implementation uses the name from `os:type/0`, with `nt` rendered as `windows_nt`; its README uses `windows_nt`, `linux`, and `darwin` for caller-side branches. This provider maps Rust's `windows` to `windows_nt`, `macos` to `darwin`, and `solaris` or `illumos` to `sunos`. Other Rust target names pass through unchanged. Only Linux, macOS, and Windows are configured for native source-backed CI validation; output on other targets has not been compared with the original Erlang package. The existing `geam-platform` provider returns `win32` on Windows for a different Gleam package and is not interchangeable with this API.

The [standalone fixture](fixtures/gleam/) and [Rust embedding fixture](fixtures/embedding/) use the original Hex package without changing its source. The source-backed contract test compares the original `gleam run` result with the Geam-hosted result on the same operating system. The standalone fixture also exercises `geam prepare`, `run`, `build`, and a built executable, while the embedding fixture exercises the generated typed binding. The original source hashes are recorded in [`fixtures/upstream.sha256`](fixtures/upstream.sha256).

The Geam dependency is pinned to `main` commit `cf5fb100c9220d9e30ff60a11d5bfbeb77f1ebef`. See the [testing guide](../docs/development/testing.md) for verification commands and the [provider compatibility policy](../docs/design/provider-compatibility.md) for the caller-visible contract. Publishing this crate and validating registry-based consumption are separate steps while Geam remains Git-pinned.
